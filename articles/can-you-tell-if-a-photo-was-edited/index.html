IMAGE FORENSICS & EDITING TRACES

Can You Tell If a Photo Was Edited? What Image Forensics Can — and Cannot — Show

A photo can carry clues about how it was saved, resized, recompressed or handled by software. Those clues can be useful. They are not the same thing as a complete edit history, an authorship record, or a universal AI detector.

Published September 11, 2026 · SIGNA AI Lab

“Edited” is a bigger question than it sounds

Opening an image in an editor and saving it again is technically an edit. So is rotating it, cropping a few pixels, changing exposure, exporting to a different JPEG quality, or taking a screenshot. A forensic review therefore needs a narrower question: what observable changes or workflow traces are present in the file we have now?

That framing matters because a file can show evidence of processing without telling you why the processing happened. Social platforms, messaging apps, cloud photo services and ordinary export tools routinely rewrite images. Detecting a rewrite is not the same as detecting deception.

Image forensics works best when it separates observation from verdict.

“This JPEG appears to have been recompressed” is a technical observation. “This photo is fake” is a much broader claim.

Metadata can identify clues, not a complete history

EXIF, XMP, IPTC and application-specific metadata can expose camera settings, timestamps, software declarations or workflow records. A software tag may show that an application wrote information into the file. It does not necessarily show that the same application created the original image or performed the only edit.

Missing metadata is equally ambiguous. Screenshots, privacy exports, messaging services and format conversions can remove fields from perfectly ordinary photos. This is why metadata is useful as context but weak as a stand-alone authenticity test. For a deeper breakdown, see What Can Image Metadata Tell You About a Photo?

JPEG recompression leaves a different kind of clue

JPEG is lossy. Saving a JPEG again introduces another compression step, which can change quantized frequency coefficients even when the picture still looks nearly identical. Analysts may inspect quantization tables, block behavior, local inconsistencies or other compression-related patterns to form a hypothesis about prior processing.

But recompression by itself does not reveal intent. A photo downloaded from a social network may have been recompressed automatically. A camera app may also encode directly to JPEG using settings that resemble a later export. The safe conclusion is about the file state, not motive.

Resize and crop change geometry

Resizing creates a new pixel grid through interpolation. Cropping removes part of the image and shifts the coordinate system of what remains. Those transformations can matter both for forensic measurements and for embedded signals such as invisible watermarks. A detector that expects a particular geometry may need to recover alignment before it can test for a signal.

This is one reason image-state analysis and watermark detection answer related but different questions. A resize clue does not prove that a watermark once existed, and a failed watermark check does not prove that one was never embedded.

Software traces are declarations, not witnesses

Some editors write their names or workflow data into files. That can be genuinely useful, especially when several compatible traces appear together. Yet metadata can be copied, stripped or rewritten. A declared application should therefore be reported as a declaration found in the current file, not promoted into a guaranteed historical fact.

What about AI-generated or AI-edited images?

This is where overclaiming becomes especially easy. There is no single universal clue that reliably classifies every image as AI-generated or not AI-generated. Some ecosystems provide their own verification mechanisms. Google, for example, uses SynthID to check for content generated or edited by Google AI tools; Google also notes that a negative SynthID result does not rule out generation by other AI systems.

That distinction is important: a system-specific signal can be strong evidence about that system while still being narrow in scope. It should not be presented as a universal AI detector.

Provenance is another evidence layer

C2PA Content Credentials use signed manifests and asset bindings to carry provenance assertions. They can help verify that certain statements are associated with a particular asset. The C2PA principles deliberately separate this from a value judgment about whether content is “good,” “bad,” or generally truthful.

Provenance can also exist outside ordinary embedded metadata. Adobe documents a possible-match mechanism that can recover cloud-stored Content Credentials even from a screenshot in supported workflows. That is different from inferring an edit solely from pixels.

A stronger review combines independent observations

Useful image review often combines several layers: file format and dimensions; metadata containers; compression state; software declarations; visible editing clues; system-specific watermark signals; and available provenance records. The value comes from agreement or tension between observations, not from forcing one clue to answer every question.

How SIGNA fits into this picture

SIGNA’s shipped Android app combines visible watermarking, an invisible SIGNA signal and on-device image review. SIGNA Inspect can present signal-related information and image-state observations, including available metadata and processing-related clues. These are reference observations with stated limitations.

SIGNA does not turn those observations into legal proof, ownership proof, originality proof, a guaranteed edit-history reconstruction or a universal AI verdict. Recompression, resizing, cropping, screenshots and platform processing can also affect what remains observable.

The right question is not “Can one tool tell me the whole truth?”

It is “What evidence is actually present, what does each piece support, and where should the conclusion stop?”
