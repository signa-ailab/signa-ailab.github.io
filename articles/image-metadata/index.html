What Can Image Metadata Tell You About a Photo?

Metadata becomes useful when you stop treating it as a mysterious “hidden data” block and start reading the exact structures and fields that are actually present. A camera tag, software declaration and AI-workflow record can sit in the same file while supporting very different conclusions.

Published September 3, 2026 · Updated September 17, 2026 · SIGNA AI Lab
What you will learn
  • How EXIF, XMP, IPTC and PNG text records differ.
  • What real-looking field patterns can look like in a camera original, edited export, workflow PNG and screenshot.
  • A five-step method for separating a stored value from the history you might be tempted to infer from it.

Metadata is a family of records, not one truth layer

FamilyTypical roleExamples
EXIFCapture and camera-related technical informationMake, model, exposure, orientation, capture time, GPS when recorded
XMPExtensible creative and asset-workflow metadataCreator tool, descriptions, dates, rights and application-specific properties
IPTCEditorial and administrative photo informationCaption, creator, location, keywords, credit
PNG text chunksText records stored in PNG containerstEXt, zTXt, iTXt, application-defined workflow information

The most important question is not simply “is there metadata?” It is which structure produced this value, and what kind of statement is that structure capable of making?

Four files, four different metadata stories

Software declaration

You may see a Software or XMP CreatorTool value naming an application. It supports that a declaration was written or preserved — not that the app created the original scene.

Workflow PNG

Application record

Some tools, including documented ComfyUI workflows, can store prompt- or workflow-related information in PNG text records. Presence is useful; absence is not a universal “not AI” verdict.

Screenshot

New capture context

A screenshot is a newly created image. The original camera EXIF is not simply copied as the camera history of the screenshot. Dimensions and metadata now describe the new capture workflow.

Shared derivative

Partial survival

A messaging or social route may preserve, rewrite or discard different fields. The returned file must be inspected; the platform name alone is not enough.

Clean export

Silence is ambiguous

No software tag can mean “not recorded,” “removed,” “not copied,” or “written elsewhere.” Missing metadata is not an untouched-original certificate.

Read metadata in this order

1
Name the container

JPEG, PNG and other formats expose different structures. Know what parser or section produced the value.

2
Preserve the exact observation

Record the key and value before interpreting it: for example, “XMP CreatorTool contains X.”

3
Ask who could write it

A camera, editor, export tool, platform or later application may have created or preserved the field.

4
Check compatibility with the rest of the file

Do dimensions, encoding state and other records tell a coherent story or create tension?

5
State the limit

Do not turn “software X is declared” into “software X created every pixel,” or missing AI workflow data into “not AI.”

Observation
An XMP CreatorTool field names an application.
Reasonable context
That application may have written, exported or preserved the current file at some stage.
Not established
Who captured the scene, which exact edit occurred, or whether that application was the first or only tool in the workflow.

Why AI-workflow metadata is interesting — and limited

Generative-image tools can leave richer records than a simple software label. ComfyUI’s documented Save Image behavior is one example: workflow information can be embedded in PNG output so a workflow can later be referenced. That can be genuinely informative when present.

But a metadata record is not an independent origin oracle. It can be copied, stripped or modified. A generated image may lose recognizable workflow metadata after export, conversion, screenshotting or platform processing. The safe language stays specific: workflow metadata observed, declared tool observed, or no such record observed in this check.

Why the same-looking image can have different metadata

Saving through another application, format conversion, privacy cleaning, screenshot capture, cloud processing and social sharing can all change a file’s metadata while leaving the visible scene nearly unchanged. The reverse is also possible: metadata can survive after the pixels have been edited.

This is why metadata should be one evidence source among several. If the question is editing, read it alongside compression state, dimensions, software traces, watermark signals and available provenance.

What metadata is good at

Metadata is valuable for context: capture settings, declared dates, location when stored, software declarations, editorial information and workflow records. It becomes misleading only when a valid observation is promoted into a stronger historical claim that the field cannot independently prove.

SIGNA LAB READING RULE

Preserve the value before telling the story.

If a report cannot distinguish “what was stored” from “what we infer,” it becomes easy to overstate weak evidence. SIGNA’s approach is to keep those layers separate.
