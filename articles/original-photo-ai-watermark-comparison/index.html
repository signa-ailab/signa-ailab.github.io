VISUAL COMPARISON · AI & WATERMARKS

Which photo is the original? Compare a watermark, AI removal, and an AI-made lookalike

Four images share the same scene, but they did not arrive there the same way. Try the comparison first, then look at what changed — and why a better sharing workflow starts before the photo leaves your device.

October 7, 2026 · SIGNA AI Lab
Before you scroll to the answer
  • A–D include a visibly watermarked image, the source photo, an AI-edited result requested to remove that watermark, and a new image generated to resemble the source.
  • This is a visual comparison, not an AI-detector benchmark.
  • The practical takeaway is about preparation: visible attribution, an optional invisible signal, later file review, and a saved report when you need one.

Quick test: which one is the original photo?

Look at A through D before opening the answer. One file is the original photo. One adds a visible “SIGNA AI Lab” watermark. One is the result of asking an AI image editor to remove that visible mark. One is a newly generated image made to resemble the original scene.

The four files are shown at the same display size for comparison. A–D are labels only; the answer is intentionally hidden below.

Show the answer and how each image was made

D is the original photo. A is that scene with a visible “SIGNA AI Lab” watermark. B is an AI-edited result produced from the watermarked version with the instruction to remove the visible mark. C is a newly generated image created to resemble the original scene rather than a copy of the original pixels.

The comparison is deliberately simple: it shows why “looks convincing” and “is the same file” are different questions.

The first trap is treating appearance as file history

A photograph can survive several transformations and still feel familiar at normal viewing size. Conversely, a newly generated image can borrow composition, lighting and subject matter without sharing the original file’s pixels or history. That is why visual similarity is useful for noticing differences, but weak as a complete account of how a file was made.

What the visible watermark does — and what changed around it

A visible watermark is still immediately useful when you want a name or brand to travel with the image. People can see it without special software. The change is that object-removal and generative editing tools can now reconstruct the area where that text or logo used to be.

In B, the editing request was simply to remove the visible watermark. The output looks plausible because the model generated replacement detail for the covered water and reflections. That does not restore hidden “original pixels”; it creates a new edited result.

The generated lookalike is a different problem

C was not made by erasing a mark from the original file. A new image was generated from a visual reference to reproduce the same kind of skyline, cherry blossoms, water and sunset composition. The overall scene can feel close while fine geometry, reflections, blossom patterns and building details drift.

Two different questions

“Does this look like the same scene?” is a visual question. “Is this the same file, or what processing path produced it?” is a file-and-workflow question. They should not be collapsed into one verdict.

What to look at when the images seem close

  • Repeated detail: branches, flowers, ripples and facade patterns are difficult to recreate with exact consistency.
  • Geometry: windows, roof lines, arches and reflections may shift in a newly generated image.
  • File state: dimensions, metadata, encoding history and other available signals describe the file you actually have, not just what it looks like.
  • Known preparation: if you prepared a sharing copy yourself, your own visible mark, SIGNA signal and local insertion record give you a clearer reference point later.

The stronger move happens before sharing

Creators do not need to wait until a suspicious copy appears. A practical workflow starts earlier: keep the source file, prepare a sharing copy, decide whether visible attribution belongs on it, and add an invisible SIGNA signal when you want a second, non-visible reference to check later.
